## 1. 业务背景与痛点

版本计划落地后，所有执行混在一起，管理层提出新问题：

- **分不清执行来源**："这次回归是流水线自动跑的，还是测试同学手动跑的？"——无法回答；
- **自动化质量无法评估**：想对比"自动化执行 vs 手工执行"的成功率差异（判断自动化用例的稳定性），数据里没有这个维度；
- **执行渠道在增加**：已有手动点击、定时任务调度、CI 流水线触发三种来源，未来还可能有灰度触发、代码提交触发等——值域必须可扩展。

**本阶段目标**：**执行方式成为"每一次执行"的属性**——同一计划可以手动执行一次、流水线再执行一次，各次独立标记、独立统计；值域做成数据字典，业务自行扩展、无需发版。

## 2. 用户与使用旅程

### 2.1 角色

| 角色 | 职责 |
|---|---|
| 项目测试负责人 | 执行时选择本次执行方式；查看用例最近一次的执行方式 |
| 测试经理 / 总监 | 在报表中按执行方式对比质量（报表侧见阶段五） |

### 2.2 用户旅程：一轮混合执行的迭代

> 负责人小王的项目已接入 CI，V2.5 计划要混合多种方式执行。

```
1. 手动冒烟
   • 计划页点"一键执行" → 弹窗选择执行方式（默认"手动执行"）→ 执行
   • 结果：本轮全部用例记为 手动执行

2. 代码合入，流水线自动回归
   • CI 通过接口触发执行，传执行方式=流水线触发执行
   • 同一个 V2.5 计划，又执行了一轮，记为 流水线触发执行

3. 夜间定时回归
   • 调度系统每晚定时触发，传执行方式=定时任务执行
   • 同一计划第三次执行，记为 定时任务执行

4. 查看区分
   • 计划用例列表：每条用例显示【最近一次】的执行方式（标签）
   • 报表中心（阶段五）：
       - 分执行方式统计：三种方式各自的次数与成功率
       - 团队/项目报表：展开看各方式的成功率对比
       - 用例明细：单用例"手动 100% vs 流水线 60%"→ 判定环境问题还是代码问题

5. 半年后新增"灰度触发"执行方式
   • 管理员在字典中添加新方式 → 执行弹窗自动多一个选项
   • 用新方式执行后，报表自动多出对应成功率列 —— 全程无需改代码、无需发版
```

**旅程验收点**：同一计划三种方式各执行一次，报表三种方式数据独立正确；新增字典方式零发版生效。

## 3. 功能需求

| 编号 | 需求 |
|---|---|
| FR-X01 | 一键执行时选择本次执行方式；默认"手动执行"；选项来自执行方式字典 |
| FR-X02 | 执行方式是**每次执行**的属性，与版本计划解绑：同一计划可多次以不同方式执行，各次独立记录 |
| FR-X03 | 计划用例列表展示每条用例最近一次执行的执行方式（未执行显示 -） |
| FR-X04 | 执行方式值域数据字典化：初始值 手动执行 / 定时任务执行 / 流水线触发执行；支持排序字段控制展示顺序 |
| FR-X05 | 字典扩展：新增方式后，执行入口选项、报表分方式统计、报表动态列、Excel 导出动态表头全部自动生效，无需系统发版 |
| FR-X06 | 值域校验：执行方式不在字典中时，接口返回明确错误 |
| FR-X07 | 外部触发友好：执行接口支持调用方（调度系统/CI）显式传执行方式，不传默认手动执行 |

## 4. 业务规则

| 规则 | 内容 |
|---|---|
| 方式挂在"执行"上，不挂在"计划"上 | 计划本身无执行方式属性；执行时现场指定（页面选择或接口传入） |
| 页面点击 = 手动执行 | 用户在页面发起且未显式指定时，默认记为手动执行 |
| 每次执行单一方式 | 一次执行的所有用例记录同一方式；方式混合靠多次执行实现 |
| 字典是唯一值域来源 | 前端选项、后端校验、报表动态列全部以字典/数据为准，代码中不硬编码值域 |

## 5. 验收要点

1. 同一计划分别以三种方式执行，计划页用例方式标签显示最后一次；报表各方式成功率独立计算；
2. 字典新增"灰度执行"后：执行弹窗出现新选项（无需刷新发版）、以新方式执行、报表自动出现"灰度执行成功率"列；
3. 接口传不存在的执行方式，返回明确错误提示；
4. 字典接口不可用时，页面有本地兜底选项（不影响基本使用）。

## 6. 范围边界（本阶段不做）

- 不做真实定时任务调度与 CI 对接（执行仍为模拟；方式字段与接口已就绪，对接属后续）；
- 不做执行方式字段的运维管理页面（字典直接数据库维护）；
- 不允许一次执行内混合多种方式。
