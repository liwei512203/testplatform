## 1. 业务背景与痛点

测试团队过去用 Excel / 各自的文档管理测试用例：

- 用例散落在个人电脑和聊天记录里，人员变动即资产流失；
- 多个系统（项目）的用例混在一起，找不到"这个系统的用例在哪"；
- 用例内容格式不统一（有人写步骤、有人只写结论），评审与执行时口径混乱。

**本阶段目标**：把测试资产结构化地管起来——**项目是容器，用例是资产**，实现"每个系统的用例有唯一权威存放处"。

## 2. 用户与使用旅程

### 2.1 角色
| 角色 | 职责 |
|---|---|
| 项目测试负责人 | 创建/维护项目信息、录入与维护用例 |

### 2.2 用户旅程：新系统接入，建立测试资产

> 测试负责人小王接到"交易系统"的测试任务，需要从零建立测试资产。

```
1. 创建项目
   • 新建项目：填写 项目名称（交易系统）、系统编号（TRADE）
   • 项目成为用例的归属容器

2. 录入测试用例
   • 在项目下新建用例：填写用例名称
   • 用例内容按统一结构编写：
       - 前置条件（如：用户已登录且账户余额充足）
       - 测试步骤（多步，可增删，如：进入详情页 → 点击购买 → 提交订单）
       - 预期结果（如：订单创建成功，页面跳转到支付页）
   • 系统同时保存一份 JSON 原文（可校验格式合法性，接口必填校验）

3. 日常维护
   • 按关键字搜索用例、分页浏览
   • 修改用例（编辑步骤/预期结果）、废弃用例（删除，二次确认）
   • 重复用例名有唯一性提示，项目名称不允许重复

4. 按项目隔离查看
   • 顶部切换到别的项目，看到的就是别的项目的用例
   • 项目删除时，该项目全部用例一并清理（级联，有确认提示）
```

**旅程验收点**：新项目接入 10 分钟内可完成"建项目→录入首批用例"；用例内容三要素齐全可指导新人执行。

## 3. 功能需求

### 3.1 项目管理

| 编号 | 需求 |
|---|---|
| FR-P01 | 新建项目：项目名称（必填，≤32字，全局唯一）、系统编号（必填，≤32字） |
| FR-P02 | 项目列表：查看全部项目，支持按名称/编号搜索 |
| FR-P03 | 编辑项目：修改名称/系统编号（保持名称唯一性校验） |
| FR-P04 | 删除项目：二次确认并明确提示"将删除项目下全部测试用例"，确认后级联删除 |
| FR-P05 | 项目切换：顶部下拉切换"当前项目"，全平台业务页面随当前项目联动 |

### 3.2 测试用例管理

| 编号 | 需求 |
|---|---|
| FR-C01 | 新建用例：归属当前项目；用例名称必填（≤32字）；用例内容为结构化三要素（前置条件/测试步骤/预期结果），存储为 JSON |
| FR-C02 | 用例内容 JSON 格式合法性校验：非法格式不允许保存并明确提示 |
| FR-C03 | 用例列表：按当前项目过滤，支持名称/内容关键字搜索、分页 |
| FR-C04 | 编辑用例：修改名称与内容（保持 JSON 校验） |
| FR-C05 | 删除用例：二次确认 |
| FR-C06 | 用例查看：抽屉展示用例详情（前置条件、步骤列表、预期结果、JSON 原文），格式对人类阅读友好 |

## 4. 业务规则

| 规则 | 内容 |
|---|---|
| 项目是用例的唯一容器 | 用例创建后归属项目不可变更；不存在"无项目用例" |
| 项目名称全局唯一 | 防止多团队同名系统混淆 |
| 用例内容三要素 | 前置条件 / 测试步骤（有序多步）/ 预期结果——保证用例可执行、可评审 |
| 级联删除 | 删项目必删用例，不留孤儿数据 |

## 5. 验收要点

1. 创建两个项目，各自录用例，互相不可见（隔离）；
2. 保存格式错误的用例内容被拦截且提示清晰；
3. 删除项目后，该项目用例确实不可再访问；
4. 顶部切换项目后，用例列表自动刷新为新项目数据，分页重置。

## 6. 范围边界（本阶段不做）

- 不做用例模块/目录分组、用例评审流、用例版本历史；
- 不做用例批量导入导出（Excel 批量导入属于后续迭代）；
- 不做富文本，用例内容为结构化文本 + JSON。
