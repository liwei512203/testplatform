# 阶段三 —— 版本计划与迭代执行业务需求

| 文档定位 | 业务需求：以迭代为单位组织测试执行、记录执行结果、沉淀执行数据 |

---

## 1. 业务背景与痛点

用例管起来之后，测试执行仍是"随做随丢"：

- **执行没有批次概念**：这轮迭代测了哪些用例、测了几轮，说不清；
- **执行结果不落库**：跑完用例结果记在聊天记录/个人笔记里，无法回顾与统计；
- **时间维度的测试无法做**：负责人想按历史时间段组织测试（如回归某版本），工具不支持自选时间。

**本阶段目标**：引入**版本计划**作为迭代容器——"一轮迭代 = 一个版本计划"，计划自动圈定本轮要执行的用例，执行结果结构化沉淀，为后续报表提供数据基础。

## 2. 用户与使用旅程

### 2.1 角色

| 角色 | 职责 |
|---|---|
| 项目测试负责人 | 创建/维护版本计划、发起执行、查看执行结果 |

### 2.2 用户旅程：一轮迭代的完整闭环

> 负责人小王为"交易系统"的 V2.5 迭代组织测试。

```
1. 创建版本计划
   • 在版本计划页点"新建"，填写：
       - 版本名称：V2.5（迭代轮次命名）
       - 计划时间：自选任意时间点（可过去可未来——支持按历史时间段回溯测试）
   • 创建后系统自动继承当前项目【全部】测试用例到该计划
     （本轮迭代所有用例都要执行；页面有明确提示）

2. 首轮执行（一键执行）
   • 点"一键执行"→ 确认弹窗（提示用例数与规则）→ 执行
   • 系统模拟执行结果：每条用例随机分配 成功（约80%）/ 失败（约20%）
   • 每条用例的执行时间 = 版本计划的计划时间（保持一致，报表归期统一）

3. 查看执行情况
   • 计划列表：每行显示 执行统计（成功X / 失败Y / 未执行Z）
   • 点"查看用例"：逐条用例的 执行结果（成功/失败/未执行）+ 执行时间

4. 回归再执行（重复执行）
   • 修复后同一计划再点"一键执行"→ 新一轮随机结果
   • 业务语义：该轮用例当天【又执行了一次】，历史执行次数累计
     （计划页显示最新一轮结果；报表统计累计全部执行次数）

5. 修改计划时间
   • 计划时间变更后，已执行用例的执行时间与统计归属日同步迁移到新日期

6. 迭代结束
   • 删除计划（级联删除该计划的用例关联与执行记录，二次确认）
   • 或保留计划作为历史数据，供报表统计
```

**旅程验收点**：创建计划无需挑选用例（自动全量继承）；执行结果立即可查；重复执行累计不丢数。

## 3. 功能需求

### 3.1 版本计划管理

| 编号 | 需求 |
|---|---|
| FR-V01 | 新建版本计划：归属当前项目；版本名称必填（≤32字）；计划时间必填且由用户指定（可为过去/未来） |
| FR-V02 | 用例自动继承：创建计划时自动关联该项目当前全部测试用例（状态"未执行"）；创建后项目用例增删不影响已建计划（快照隔离） |
| FR-V03 | 计划列表：按计划时间倒序，展示用例总数与执行统计（成功/失败/未执行） |
| FR-V04 | 编辑计划：可改版本名称与计划时间；不允许变更所属项目 |
| FR-V05 | 计划时间变更联动：该计划已执行用例的执行时间与执行记录归属日期同步迁移 |
| FR-V06 | 删除计划：二次确认，级联删除计划-用例关联及执行记录 |
| FR-V07 | 无用例的计划不可执行（按钮置灰，接口报明确错误） |

### 3.2 一键执行（模拟执行）

| 编号 | 需求 |
|---|---|
| FR-E01 | 一键执行：对该计划下全部用例模拟执行，随机分配结果（成功约80% / 失败约20%），完成后提示"成功X条，失败Y条" |
| FR-E02 | 执行时间规则：所有用例的执行时间与版本计划计划时间严格一致 |
| FR-E03 | 重复执行：同一计划可多次执行；计划页展示最新一轮结果，执行记录按次累计 |
| FR-E04 | 执行前确认：弹窗说明将执行的用例数量与规则 |

### 3.3 计划用例查看

| 编号 | 需求 |
|---|---|
| FR-Q01 | 计划用例列表：用例ID、名称、执行结果（成功绿/失败红/未执行灰）、执行时间（未执行显示-）、分页 |
| FR-Q02 | 抽屉头部展示计划时间与三类统计 |

## 4. 业务规则

| 规则 | 内容 |
|---|---|
| 计划=迭代容器 | 一个项目可建多个计划；计划间数据完全隔离 |
| 全量继承 | 创建时继承项目全部用例（简化规则，不挑选）；后续需求可扩展为勾选 |
| 快照隔离 | 计划创建后与项目用例解耦，保证历史计划口径稳定 |
| 执行时间=计划时间 | 所有执行记录归属计划时间所在日期，保证"按时间段做测试"可回溯 |
| 执行记录永久累计 | 重复执行不覆盖历史——最新结果供页面看，历史次数供报表算 |

## 5. 验收要点

1. 创建计划后项目新增用例，计划用例数不变（快照隔离）；
2. 执行后每条用例执行时间 = 计划时间（精确到秒）；
3. 同一计划执行 3 次，执行记录中该计划累计 3 轮（次数=用例数×3）；
4. 修改计划时间后，执行记录的归属日期同步迁移；
5. 删除计划后其执行记录不可再查，项目用例不受影响。

## 6. 范围边界（本阶段不做）

- 执行为**模拟执行**（随机结果），不真正调用自动化框架/接口；
- 不支持计划内用例挑选/排除（全量继承）；
- 不支持单人逐条执行/执行人记录（无用户体系）；
- 不做执行日志页面化查看（执行明细通过报表体现）。
