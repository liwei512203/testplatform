## 1. 业务背景与痛点

平台上线后多团队共用，出现新的组织问题：

- **不知道系统是谁的**：几十个系统的项目堆在一个列表里，不知道"信贷系统归哪个测试团队管"；
- **找项目费劲**：负责人每次要在几十个项目里翻找自己负责的那几个；
- **功能入口乱**：用例、版本计划、报表等功能上线后没有统一入口，操作路径不清晰。

**本阶段目标**：**项目挂上组织归属（测试团队），平台形成统一工作台**——任何页面都知道"我现在在看哪个项目"，任何功能三步可达。

## 2. 用户与使用旅程

### 2.1 角色

| 角色 | 职责 |
|---|---|
| 测试经理 | 按团队筛选查看项目、维护项目团队归属 |
| 项目测试负责人 | 快速切换自己负责的项目，进入对应功能模块 |

### 2.2 用户旅程：经理分配团队归属，负责人日常工作

```
【测试经理视角】
1. 进入"项目列表"页
   • 看到 22 个项目：名称、系统编号、测试团队（彩色标签）、是否当前项目
   • 按"企金测试团队"筛选 → 只看到本团队 5 个项目
2. 新项目"供应链系统"立项 → 新建项目时选择测试团队"企金测试团队"
3. 组织调整：某项目划归零售团队 → 编辑项目改团队归属

【项目负责人视角】
1. 早上打开平台，顶部下拉直接选"交易系统"（记住上次选择）
2. 左侧菜单一眼看到三大功能模块：测试用例 / 版本计划 / 数据报表
3. 点"测试用例"维护用例；切到"版本计划"安排迭代；切"数据报表"看执行情况
   —— 三个模块都自动跟随"当前项目"，无需重新选项目
4. 需要管理项目（建新项目/改归属/删项目）→ 顶部"项目列表"按钮进入管理页
```

**旅程验收点**：负责人从打开平台到进入任一功能模块 ≤2 次点击；经理能在 10 秒内筛出本团队项目清单。

## 3. 功能需求

### 3.1 测试团队归属

| 编号 | 需求 |
|---|---|
| FR-T01 | 项目新增"测试团队"属性，值域固定四项：企金测试团队 / 零售测试团队 / 数据测试团队 / 公共测试团队 |
| FR-T02 | 新建/编辑项目时必选测试团队（前端下拉仅四项；接口对非法值返回明确错误） |
| FR-T03 | 项目列表展示团队标签（颜色区分），支持按团队筛选，可与关键字搜索组合 |
| FR-T04 | 项目团队可变更；变更后报表中的团队归属随之更新（为阶段五打基础） |

### 3.2 项目管理页

| 编号 | 需求 |
|---|---|
| FR-N01 | 独立"项目列表"页：全部项目、团队筛选、关键字搜索、新建、编辑、删除 |
| FR-N02 | "切换项目"操作：将目标项目设为当前项目并跳转回业务页面 |
| FR-N03 | 当前行标识：列表中标记哪个是当前项目 |

### 3.3 统一工作台

| 编号 | 需求 |
|---|---|
| FR-N04 | 顶部项目选择器：可搜索下拉，切换后全平台业务页面联动刷新；记住上次选择（刷新页面不丢失） |
| FR-N05 | 顶部"项目列表"入口：从下拉底部与按钮两处可达项目管理页 |
| FR-N06 | 左侧菜单：测试用例 / 版本计划 / 数据报表 三大模块，当前路由高亮 |
| FR-N07 | 未选择项目（如项目全删）时，业务页展示空态并引导前往项目列表 |

## 4. 业务规则

| 规则 | 内容 |
|---|---|
| 团队是项目属性 | 一个项目同一时间只归属一个团队；组织调整时改归属而非重建项目 |
| 当前项目是会话级上下文 | 所有业务模块跟随当前项目；切换即刷新，不残留上一项目的数据 |
| 团队值域暂固定 | 四个团队为当前组织现状；后续如团队增加，可参照阶段四的字典化方案改造 |

## 5. 验收要点

1. 新建项目不选团队无法保存；接口传非法团队值返回明确错误信息；
2. 团队筛选 + 关键字搜索可组合使用，结果正确；
3. 切换当前项目后，用例/版本计划/报表页数据全部联动，刷新浏览器后当前项目保持；
4. 删除当前项目后自动切换到其他项目（或空态引导），页面无报错。

## 6. 范围边界（本阶段不做）

- 不做用户-团队绑定与权限（所有用户可管所有项目）；
- 团队值域不做动态字典（固定四值，扩展时另行改造）；
- 不做多级组织（部门→小组→团队）。
