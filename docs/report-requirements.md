## 1. 业务背景与价值

### 1.1 业务痛点

测试管理平台承载公司十几个测试团队、几十个系统的测试活动，每天产生大量用例执行。管理层与测试负责人当前面临：

| 角色 | 痛点 |
|---|---|
| 测试总监 | "全公司今天/这周/这个月测了多少？质量怎么样？哪个团队拖后腿？"——没有统一视图，只能挨个团队问 |
| 测试经理 | "我团队5个项目，哪个项目执行量上去了但质量在下滑？"——数据散在各项目，无法横向对比 |
| 项目负责人 | "这轮测试哪些用例总在失败？自动化（流水线）跑的和手动跑的质量有差别吗？"——失败用例靠翻执行记录，分不出执行来源 |

### 1.2 业务目标

提供一套**三级下钻的执行报表**：

```
看全局（系统报表）→ 找团队（团队报表）→ 定项目（项目报表）→ 抓用例（失败TOP/明细）
```

让不同角色在 3 次点击内，从"全公司质量大盘"定位到"那个总失败的用例"。

## 2. 用户与使用场景（User Journey）

### 2.1 用户角色

| 角色 | 关注点 | 高频动作 |
|---|---|---|
| 测试总监 / 测管管理者 | 全局规模与质量、团队对比、环比趋势 | 看系统报表、扫团队报表 |
| 测试经理 | 本团队项目健康度、劣化项目、执行覆盖 | 团队报表、下钻项目 |
| 项目测试负责人 | 单项目失败用例、执行来源分析、导出汇报 | 项目报表、失败TOP、明细、导出 |

### 2.2 用户旅程一：总监的周一晨会（系统报表）

> 张总监每周一晨会要向质量 VP 汇报上周全公司测试情况。

```
进入"数据报表"
   │
   ├─ 默认看到【近30天】的系统报表
   │     • 6 张指标卡：项目总数 / 执行次数 / 覆盖用例数 / 执行率 / 成功率 / 失败次数
   │     • 每张卡片带环比角标（"执行次数 +12.5%↑ 绿色"，一眼看出趋势好坏）
   │
   ├─ 想看"上周"→ 改时间范围为上周一~上周日
   │     • 所有卡片、趋势图、分方式统计同步刷新
   │     • 卡片环比自动变为"上上周"对照
   │
   ├─ 晨会讲解【每日执行趋势图】
   │     • 柱子=每天执行量，绿线=成功率，两条轴不冲突
   │     • 浅色柱/虚线是上一周期对照，讲"环比走势"很直观
   │     • 选的时间长（>60天）自动变成按周聚合，图不糊
   │
   ├─ VP 问"自动化跑得怎么样？"→ 看【分执行方式统计】表
   │     • 手动/定时任务/流水线各一行：次数、成功、失败、成功率
   │     • 直接回答"流水线成功率 82%，比手动低 1 个点"
   │
   └─ 汇报材料需要原始数据 → 点【导出Excel】拿到团队报表文件
```

**旅程验收点**：改时间范围后全部联动；环比方向符合直觉（失败上升=红色警示）；导出文件可直接贴进 PPT。

### 2.3 用户旅程二：经理的团队健康巡检（团队报表）

> 李经理管"零售测试团队"，每周巡检团队 5 个系统的测试情况。

```
切到【团队报表】页签
   │
   ├─ 看团队一览表（每队一行，按执行量排序）
   │     • 找到自己团队：项目数、执行次数、覆盖用例数、总用例数、
   │       执行率、成功/失败、成功率、执行环比
   │     • "执行环比 -40%" 标红 → 本团队这周执行量掉了，先注意
   │
   ├─ 心里犯嘀咕"是不是质量不行手动补测多？"
   │     → 点成功率列头的【展开按钮】
   │     • 展开出"手动成功率 / 定时任务成功率 / 流水线触发成功率"列
   │     • 各团队分方式对比，看谁的手动成功率异常低
   │     • 平时收起不占地方，要用再展开（再点收起）
   │
   ├─ 点本团队行的【项目下钻】
   │     • 进入"零售测试团队 - 项目执行情况"列表
   │     • 5 个项目横向排开：谁的执行量掉了、谁的成功率垫底一目了然
   │     • 同样有分方式成功率（收起式）和执行环比
   │     • 发现"零售-支付系统06"执行量翻倍但成功率掉到 82% → 锁定问题项目
   │
   ├─ 需要拉项目组对齐 → 【导出Excel】把项目列表发给项目负责人
   │
   └─ 点【返回】回到团队一览，继续看下一个团队
```

**旅程验收点**：下钻→返回状态保持；0 执行团队也显示（0 值行）不"消失"；分方式展开/收起在下钻页同样可用。

### 2.4 用户旅程三：负责人的问题定位（项目报表）

> 王负责人接到经理反馈，来查"零售-支付系统06"的失败用例。

```
切到【项目报表】页签（默认带出他当前所在项目）
   │
   ├─ 顶部下拉切换到"零售-支付系统06"
   │
   ├─ 先看 4 张指标卡 + 执行趋势图
   │     • 确认执行率 100%（用例都被跑过了）
   │     • 趋势图看成功率哪天开始下滑
   │
   ├─ 右侧【失败 TOP10 用例】
   │     • 直接列出失败最多的 10 条用例 → 问题用例候选名单
   │
   ├─ 要看全量 → 点【查看用例执行明细】（平时收起，不拖慢页面）
   │     • 明细表默认按【失败次数倒序】：最差的用例排最前
   │     • 列：用例ID/名称、执行次数、成功/失败、成功率、最近执行日期
   │     • 点成功率列头【展开按钮】→ 看"这条用例手动跑的成功率 vs 流水线跑的成功率"
   │       （发现某用例流水线 60%、手动 100% → 大概率环境问题而非代码问题）
   │     • 可按成功率升序排（找最不稳的用例）、按执行次数排、搜用例名
   │
   ├─ 周会要汇报 → 【导出Excel】全量明细（最多10万行，超了会提示收窄时间）
   │
   └─ 定位完毕，带着 TOP 失败用例清单去找开发
```

**旅程验收点**：进入页面明细不自动加载（快）；展开才查询；切换项目明细自动收起重置；分方式列随翻页自动适应。

## 3. 功能需求明细（按页面）

### 3.1 报表中心框架

| 编号 | 需求 |
|---|---|
| FR-001 | 入口为左侧菜单"数据报表"，页面含三个页签：系统报表 / 团队报表 / 项目报表 |
| FR-002 | 顶部全局时间范围选择：默认近 30 天（止于昨天）；最长 366 天；不可选未来日期 |
| FR-003 | 页面常驻"数据截至：{昨天}"提示，明确告知数据为 T+1（当天执行数据次日可见，需要即时可手动刷新） |
| FR-004 | 时间范围变更后，当前页所有内容联动刷新；页签切换保留时间条件 |
| FR-005 | 趋势展示粒度自适应：≤60 天按日、更长按周（用户无感知切换） |

### 3.2 系统报表（总监视角）

| 编号 | 需求 |
|---|---|
| FR-101 | 指标卡：项目总数、执行次数、覆盖用例数、执行率、整体成功率、失败次数；除执行率/覆盖外均显示环比角标（升好绿/劣化红） |
| FR-102 | 每日执行趋势图：柱=执行量、线=成功率（双轴），叠加上一周期对照（浅色），支持按日/按周 |
| FR-103 | 分执行方式统计表：每种有执行记录的方式一行（方式、次数、成功、失败、成功率）；方式值域动态扩展（见 FR-501） |
| FR-104 | 团队报表可导出 Excel（内容同团队一览表） |

### 3.3 团队报表（经理视角）

| 编号 | 需求 |
|---|---|
| FR-201 | 团队一览：每团队一行（项目数、执行次数、覆盖用例数、总用例数、执行率、成功/失败、成功率、执行环比），按执行量倒序 |
| FR-202 | 有项目但无执行数据的团队以 0 值行展示（团队不"消失"） |
| FR-203 | 分方式成功率采用**收起式交互**：成功率列头提供展开按钮，点击显示各执行方式成功率列，再点收起（默认收起） |
| FR-204 | 团队行"项目下钻"→ 该团队项目列表（项目名、系统编号、执行量、覆盖、总用例、执行率、成功率、分方式成功率收起式、执行环比），可返回且状态保持 |
| FR-205 | 团队一览与项目列表均可导出 Excel（分方式成功率列为动态表头，随数据自动增列） |

### 3.4 项目报表（负责人视角）

| 编号 | 需求 |
|---|---|
| FR-301 | 项目选择器默认联动当前项目，可切换任意项目 |
| FR-302 | 指标卡：执行次数、覆盖用例数、执行率、整体成功率、失败次数（带环比，执行率除外） |
| FR-303 | 执行趋势图：同系统报表，限定单项目 |
| FR-304 | 分执行方式统计表：同系统报表，限定单项目 |
| FR-305 | 失败 TOP10：区间内失败次数前十的用例（用例名、失败次数、成功率） |
| FR-306 | 用例执行明细：默认按失败次数倒序；支持服务端排序（失败/成功率/执行次数/最近执行日期）、分页、用例名搜索 |
| FR-307 | 明细分方式成功率：收起式（同 FR-203），支持"手动 vs 流水线"单用例对比 |
| FR-308 | 明细懒加载：进入页面不自动加载明细，点击"查看用例执行明细"才查询；切换项目自动收起重置 |
| FR-309 | 明细导出 Excel：上限 10 万行，超限引导收窄时间范围 |

### 3.5 执行方式与数据维护（业务规则）

| 编号 | 需求 |
|---|---|
| FR-401 | 执行方式是**每次执行**的属性：同一版本计划可分别以手动/定时任务/流水线执行，各次独立计入对应方式统计 |
| FR-402 | 一键执行时选择本次执行方式（默认手动执行） |
| FR-403 | 环比对照区间=所选区间向前平移等长天数；失败类指标上升显示红色（劣化警示） |
| FR-501 | 执行方式值域由数据字典维护：业务新增执行方式（如"灰度执行"）只需管理员添加字典项，执行弹窗、报表列、导出列自动出现，**无需发版** |

### 3.6 数据时效与运维（对业务方透明的能力）

| 编号 | 需求 |
|---|---|
| FR-601 | 报表数据每日凌晨自动更新（T+1）；页面显示"数据截至"日期 |
| FR-602 | 提供手动刷新能力：指定日期/区间立即重算（验证数据、即时看数） |
| FR-603 | 提供全量重算能力：自动覆盖历史全部日期，用于口径调整后的整体重建 |

## 4. 业务规则与口径（业务方必须理解的部分）

| 指标 | 业务含义 | 常见误区澄清 |
|---|---|---|
| 执行次数 | 每执行一次计 1 次（重复执行累计） | 不是"用例条数"——1 条用例跑 3 次=3 次 |
| 覆盖用例数 | 该时间段内至少被执行过 1 次的用例数（去重） | 衡量"测没测过"，与执行次数配套看 |
| 总用例数 | 当前系统里的用例存量 | 不随所选时间变化 |
| 执行率 | 覆盖用例数 ÷ 总用例数 | 回答"这轮测试覆盖全不全" |
| 成功率 | 成功次数 ÷ 执行次数 | 跨所有执行方式汇总 |
| 分方式成功率 | 按手动/定时/流水线分别计算 | 用于对比"自动化质量 vs 手工质量" |
| 环比 | 与前一个等长时间段比较 | 选 31 天就比前面 31 天；方向语义：失败上升=红 |
| 数据截至 | 报表数字到昨天为止 | 当天执行完想立即看报表→需要手动刷新或等次日 |

## 6. 范围边界（本期不做）

- 不做用户登录/权限分级（所有角色看全部数据，后续按角色过滤）
- 不做系统级"全公司失败用例排行"（数据量不可控，排行到项目粒度为止）
- 不做执行率/覆盖数的环比（历史存量口径无法回溯，待后续快照方案）
- 不做报表定时邮件推送、周报自动生成（后续迭代）
- 不做缺陷（bug）关联分析（平台尚无缺陷实体）
- 不做实时报表（T+1 跑批口径，当天数据靠手动刷新）
